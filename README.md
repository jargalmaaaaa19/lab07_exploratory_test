## Агуулга

- `charter.md`: session-ээс өмнө бичсэн charter
- `session-report.md`: 60 минутын session-ий тайлан, түүхий тэмдэглэлтэй
- `bugs/`: алдааны тайлангууд (BUG-01 ... BUG-06)
- `evidence/`: API согогийн `curl -i` гаралт
- `screenshots/`: UI согогийн скриншот

## Дүгнэлт (debrief)

Charter-даа Supermodel (GUI) ба Saboteur (API) гэсэн хоёр аялал сонгосон. Supermodel аялал хамгийн үр дүнтэй байсан: формд хэвийн бус болон хоосон утга оруулахад BUG-03, BUG-04, BUG-06 тэр дороо илэрч, хайлт ба хүснэгтийг ажиглахад BUG-02, BUG-05 олдсон. Saboteur аялалаар curl-ээр буруу JSON илгээхэд API 400 биш 200 OK буцаадаг (BUG-01) нь баталгаажсан. Charter-аас гадуур санамсаргүйгээр Устгах товч улаан биш байгааг тэмдэглэсэн, мөн оныг `1,971` гэж таслалтай харуулж байгааг анзаарсан боловч тусдаа bug report болгоогүй. Шалгагдаагүй үлдсэн зүйл: бүх хуудас, линкийн ажиллагаа, маш урт оролт хүснэгтийг эвдэх эсэх, тусгай тэмдэгт хүснэгтэд зөв харагдах эсэх, мессежүүдийн үсгийн алдаа. Дараагийн session-ий charter нь тусгай тэмдэгт болон урт оролтын харагдац, мөн API-ийн бусад хүсэлтийг гол чиглэл болгоно. Playwright автомат тест BUG-01 (статус код шалгаж), BUG-03, BUG-04, BUG-06 болон BUG-05-ыг (өгөгдөл ба DOM-ийн утга шалгах тест бичсэн бол) барих байсан. BUG-02-ыг тохирох тест бичсэн бол барина, гэхдээ «том/жижиг үсгээр хайвал яах вэ» гэдгийг хүн бодож байж тест бичих ёстой. Устгах товчны өнгө, мессежийн утга ба үсгийн алдааг автомат тест ихэвчлэн барьдаггүй тул хүний нүд хэрэгтэй. Exploratory тест нь урьдчилан бичээгүй асуултыг гаргаж ирдгээрээ автомат тестээс ялгаатай, харин автомат тест олдсон согогийг дахин гарахаас хамгаалдаг.
